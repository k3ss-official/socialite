# Socialite design direction

The first priority is a working research, review and preview pipeline. Then develop
client-branded pages whose typography, composition, interaction and craft are
recognisably Socialite without replacing each client's identity with a house template.

## Principles

- Match the page to the business and its job: enquiries/bookings for hire, menus/hours for hospitality.
- Use the client's voice, palette and permitted real assets. Avoid generic slogans, invented claims and stock-looking filler.
- Make type, spacing, hierarchy, responsive behavior and useful interactions deliberate.
- Use motion to explain or emphasise, with reduced-motion support; it should not obstruct reading or booking.
- Keep a consistent visual language within each deliverable and record approved directions and rejected choices.
- Record asset source, permissions, generation parameters and actual usage costs when generation is used.

The classic site template is currently the supported renderer. A signature system,
creative tool adapters and finished Higgsfield assets are not yet implemented. The
user has reported around 6,000 credits; no credits have been spent in this cleanup.

## Inputs and decisions

Use approved Bible content, page objective, actual kit/premises photographs where
available, placement formats, brand references and the agreed scope/budget. Existing
user authorisation takes precedence over old draft gate rules. Do not require four
nonexistent governance files to begin already-authorised work. Confirm missing facts
or expensive scope choices when genuinely needed; publication and outreach remain
separate from creating a reviewable preview.

Do not generate something that purports to show equipment or a service the client
does not supply. Keep concept visuals distinguishable from representations of real
stock. Asset reuse rights require a recorded basis even when an image is public.

## Older creative experiments

The retired creative branch explored cinematic chapters, a reading-progress indicator,
scroll reveals, reduced-motion behavior and offline site packaging. Its original code
and generated media are retained in the pre-cleanup Git bundle, not copied into the
active product. These are reference ideas for future design work, not approved ALO assets.

The old cinema template derived aggregate ratings from selected quotes, and its offline
packager hard-coded Scran Away copy and asset names. Those implementations were not
merged. Any future theme must use the current reviewed content contract and separately
sourced review aggregates. Client-specific media belongs in backed-up runtime storage,
not in every code clone.
